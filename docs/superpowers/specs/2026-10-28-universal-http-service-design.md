# Универсальный HTTP-сервис объектов 1С

## Цель

Один HTTP-сервис расширения описывает, ищет, читает и создает справочники и документы демонстрационной конфигурации БСП. Счет на оплату покупателю создается тем же маршрутом, что и любой другой документ. Описание типа достаточно полное, чтобы внешний ассистент нашел тип, прочитал поля и собрал тело запроса.

Стартовая точка — расширение `СчетаМагазина`. Корень сервиса уже `objects`, пять обработчиков отвечают `501`. Преобразование значений, схема полей и конверт ошибок лежат в общих модулях и остаются правилами обмена.

## Решения

- Группы справочника не создаются. Поиск возвращает только элементы. Чтение группы по идентификатору выполняется. Родитель элемента можно передать.
- Подчиненный справочник создается только с владельцем. Поиск подчиненного справочника идет по наименованию по всем владельцам.
- Чтение возвращает все реквизиты и все строки табличных частей. Значение неподдерживаемого типа в ответе — `null`, запрос при этом успешен.
- Код остается в двух общих модулях и модуле HTTP-сервиса. Новые объекты метаданных не добавляются. Привилегированный режим не включается.
- Имена типов в JSON: `Справочник.Имя`, `Документ.Имя`, `Перечисление.Имя`. Кодирование значений (пустая ссылка как `null`, дата ISO 8601, UUID, имя значения перечисления, оболочка `type`/`value` для составного поля, конверт ошибки, `header`/`tables`) сохраняется от сервиса счетов.

## Границы поддержки

Поддерживаются справочники и документы конфигурации, их реквизиты и табличные части.

Значения, которые сервис читает и записывает: строка, число, дата, булево, ссылка на справочник, ссылка на документ, значение перечисления. Составное поле записывается, если каждый его тип поддерживается. Поле, среди типов которого есть неподдерживаемый, недоступно для записи.

Неподдерживаемые типы значения (хранилище значения, уникальный идентификатор, составной тип с неподдерживаемой частью, дата только со временем и прочие) видны в описании: `kind` равен `unsupported`, `writable` равен `false`, у поля есть `reason`. Запись такого поля отклоняется. Чтение объекта из-за него не падает: в JSON стоит `null`.

Общие реквизиты конфигурации, дополнительные реквизиты и сведения БСП в обмен не входят. Табличная часть `ДополнительныеРеквизиты` описывается и читается, запись в нее отклоняется с причиной, что дополнительные свойства БСП этой версией не поддерживаются.

Изменение, удаление и проведение не входят в сервис. Регистры, константы, отчеты, обработки и прочие виды метаданных отклоняются как неподдерживаемый вид.

## Модули

Имена, флаги сервера и отсутствие привилегированного режима не меняются.

`СчетаМагазинаМетаданные` разрешает имя типа и строит схему конкретного справочника или документа. Сюда входят описание поля, описание типа значения и список стандартных реквизитов, которые можно писать.

`СчетаМагазинаДанные` по готовой схеме преобразует JSON, проверяет ссылки, ищет, читает, заполняет объект и создает его. Имя объекта в тексте запроса берется из уже найденного метаданного, а не из сырой строки клиента.

Модуль HTTP-сервиса `СчетаМагазина` разбирает параметры и тело, вызывает общие модули и ставит код ответа. Корень URL — `objects`. Шаблоны `/types`, `/type`, `/search`, `/object` уже заведены.

## Имя типа

Допустимая форма — `Вид.Имя`: вид, точка, имя метаданного. Пробелов нет.

- `Справочник.Имя` или `Документ.Имя`, и объект метаданных есть: сервис работает с ним.
- Тот же вид, но объекта нет: `404`, код `unknown_type`.
- Другой вид (`РегистрСведений.Имя` и любой иной): `400`, код `unsupported_type`.
- Строка без точки, пустое имя или лишние точки: `400`, код `invalid_request`.

## Описание типа

`GET /type?name=<Вид.Имя>` возвращает `200` и схему. Права на данные для этого маршрута и для `GET /types` не проверяются: это метаданные.

```json
{
  "type": "Справочник._ДемоПартнеры",
  "kind": "catalog",
  "title": "Демо: Партнеры",
  "hierarchical": true,
  "hierarchy": "foldersAndItems",
  "subordinate": false,
  "owners": [],
  "fields": [],
  "tables": [],
  "rules": {}
}
```

`kind` документа — `document`. `hierarchy`: `foldersAndItems`, `items` или `none`. `owners` — массив имен `Справочник.Имя`. `title` — представление метаданных.

Поле:

```json
{
  "name": "Наименование",
  "title": "Наименование",
  "writable": true,
  "required": true,
  "types": [
    { "name": "string", "kind": "string", "length": 150, "fixedLength": false }
  ]
}
```

Незаписываемое поле дополнительно содержит `reason`.

Типы значений:

| kind | name | Дополнительно |
| --- | --- | --- |
| string | string | `length`, `fixedLength` |
| number | number | `digits`, `fractionDigits`, `nonnegative` |
| boolean | boolean | |
| date | date | `parts`: `date` или `dateTime` |
| catalog | Справочник.Имя | `catalog`, `searchUrl` |
| document | Документ.Имя | `document`, `searchUrl` |
| enum | Перечисление.Имя | `enumeration`, `values`: `{name, title}` |
| unsupported | строка типа платформы | |

`searchUrl` — путь от корня сервиса, например `/search?type=Справочник._ДемоПартнеры`.

`required` у обычного реквизита и у табличной части берется из проверки заполнения «выдавать ошибку». У стандартного реквизита `required` истинен только в случаях из списка ниже: всегда у `Владелец` и `Дата`, а у `Наименование`, `Код` и `Родитель` — если у них проверка заполнения «выдавать ошибку». Определяемый тип отдельным `kind` не описывается: в схему попадают фактические типы и квалификаторы `Реквизит.Тип`.

Записываемые стандартные реквизиты справочника:

- `Наименование`, если длина наименования больше нуля. Обязательность — из проверки заполнения.
- `Код`, если длина кода больше нуля. Обязательность — из проверки заполнения.
- `Родитель`, если справочник иерархический. Тип — ссылка на этот же справочник. По умолчанию не обязателен.
- `Владелец`, если справочник подчиненный. Обязателен всегда. Несколько владельцев дают составное поле.

`ЭтоГруппа` только для чтения. Причина: группы этим сервисом не создаются. Остальные стандартные реквизиты (`Ссылка`, `ПометкаУдаления`, `Предопределенный`, `ИмяПредопределенныхДанных` и прочие) только для чтения. Причина: поле назначает 1С.

У документа записывается `Дата`, и она обязательна. `Номер`, `Проведен`, `Ссылка`, `ПометкаУдаления` только для чтения. Причина у `Проведен`: документ записывается непроведенным. У остальных: поле назначает 1С.

Стандартные реквизиты табличной части только для чтения. Собственные реквизиты табличной части записываются, кроме табличной части `ДополнительныеРеквизиты`.

Правила в схеме:

- `validation` — окончательное решение принимает штатная проверка заполнения; условные правила зависят от данных и настроек базы.
- `dates` — ISO 8601 без часового пояса, местное время базы.
- `null` — штатное пустое значение; обязательность проверяет 1С, кроме владельца подчиненного справочника.
- `values` — сервис не вычисляет реквизиты и записывает переданные значения.

## Поиск типов

`GET /types?q=<слово>` ищет подстроку без учета регистра в имени и в представлении справочников и документов. Пустой или пробельный `q` — `400`, код `invalid_request`.

Ответ `200`:

```json
{
  "items": [
    {
      "name": "Документ._ДемоПоступлениеТоваров",
      "title": "Поступление товаров",
      "kind": "document"
    }
  ],
  "hasMore": false
}
```

Лимит — 20 записей. Запрос собирает 21-ю, чтобы выставить `hasMore`. Порядок — по имени метаданного. Пустая выборка — `200`, `items` пустой, `hasMore` ложен.

## Поиск объектов

`GET /search?type=<Вид.Имя>&q=<строка>`. Пустой `type` или пустой `q` — `400`, код `invalid_request`. Нет права чтения — `403`, код `forbidden`.

Справочник: `Наименование` содержит строку, без пометки удаления, без групп (для иерархии групп и элементов). Подчинение владельцу на поиск не влияет.

Документ: `Номер` содержит строку, без пометки удаления. Проведенные документы в выборку входят.

Экранирование шаблона — `ОбщегоНазначения.СформироватьСтрокуДляПоискаВЗапросе`, спецсимвол `~`. Текст запроса с `ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 21` и параметром шаблона. Порядок справочника — наименование, ссылка. Порядок документа — номер, ссылка.

Ответ `200`. Элемент справочника: `id`, `name`. Элемент документа: `id`, `number`, `date`. `hasMore` — истина, если нашлась 21-я строка. В `items` не больше 20 элементов. Пустая выборка, в том числе из-за ограничения RLS при имеющемся праве чтения, — `200` и пустой `items`.

Группа через поиск не возвращается. Идентификатор группы для родителя вызывающая сторона уже знает либо получает его чтением по `id`.

## Чтение

`GET /object?type=<Вид.Имя>&id=<uuid>` возвращает `200`:

```json
{
  "type": "Документ._ДемоСчетНаОплатуПокупателю",
  "id": "uuid",
  "header": {},
  "tables": {}
}
```

В `header` есть каждое поле схемы, включая незаписываемые. В `tables` есть каждая табличная часть и каждая ее строка со всеми полями строки.

Поддерживаемое значение кодируется так:

- пустая ссылка, пустое перечисление и пустая дата — `null`;
- число и булево — как есть, включая `0` и `false`;
- дата — `yyyy-MM-dd` или `yyyy-MM-ddTHH:mm:ss`;
- ссылка — строка UUID ровно в виде `Строка(УникальныйИдентификатор)`, 36 символов; другой регистр или форма отклоняются при записи;
- перечисление — имя значения;
- составное поле с поддерживаемыми типами — `{ "type": "<name из описания>", "value": ... }`.

Если фактический тип значения неподдерживаемый, в поле `null`.

Группа читается тем же маршрутом, `ЭтоГруппа` в ответе истинно. Помеченный на удаление объект по идентификатору читается. Нет права чтения — `403`. Ссылка не указывает на существующий объект — `404`, код `not_found`. Некорректный UUID — `400`, код `invalid_request`.

## Преобразование

Ограничения сервиса счетов сохраняются. Строка принимается, если ее длина не больше `length`; при `fixedLength` длина равна `length`. Число принимается, если оно укладывается в `digits` и `fractionDigits` и соблюдает `nonnegative`. Дата принимается строкой ISO и после разбора совпадает с канонической строкой сервиса. Перечисление принимается по имени значения. `null` во входе — пустое значение этого типа. Составное поле с несколькими поддерживаемыми типами передается объектом `type` и `value`.

## Создание

`POST /object`, тело — объект JSON:

```json
{
  "type": "Справочник._ДемоПартнеры",
  "header": {
    "Наименование": "Ромашка",
    "ВидПартнера": "ЮридическоеЛицо"
  },
  "tables": {}
}
```

`type`, `header` и `tables` обязательны. Лишние ключи корня, неизвестные поля и неизвестные табличные части — ошибки проверки. `tables` для справочника без табличных частей — пустой объект.

Успех — `201` и `{ "id": "<uuid>" }`.

Справочник создается методом `СоздатьЭлемент`. `СоздатьГруппу` не вызывается. Переданное поле `ЭтоГруппа` отклоняется до записи: `400`, код `unsupported`, путь `header.ЭтоГруппа`.

У подчиненного справочника отсутствие `Владелец` или пустой владелец — `400`, код `validation`, путь `header.Владелец`. Несколько типов владельца передаются оболочкой `type`/`value`. Владелец должен быть непромеченным элементом одного из справочников-владельцев.

`Родитель` необязателен. Для иерархии групп и элементов родитель — существующая непромеченная группа того же справочника. Для иерархии элементов родитель — существующий непромеченный элемент. Нарушение — `400`, код `validation`, путь `header.Родитель`.

Ссылка в обычном реквизите — непромеченный элемент справочника или существующий непромеченный документ, включая проведенный. Группа в таком реквизите не принимается. Проверка ссылки учитывает право чтения и запрос `ВЫБРАТЬ РАЗРЕШЕННЫЕ`.

Документ записывается в режиме `РежимЗаписиДокумента.Запись` и остается непроведенным. Номер назначает платформа.

Запись идет одной транзакцией:

1. Проверить вид, группу, владельца и родителя.
2. Преобразовать тело. Если есть ошибки преобразования, транзакция не начинается, ответ `400`, код `validation`.
3. Проверить право добавления. Нет права — `403`.
4. Начать транзакцию, создать объект, заполнить преобразованными полями.
5. Вызвать штатную `ПроверитьЗаполнение`. Отказ — отмена транзакции и `400`, код `validation`, сообщение «Штатная проверка заполнения не пройдена». Пути сообщений сопоставляются со схемой точно: `header.<Поле>` или `tables.<Таблица>[<индекс>].<Поле>`. Сообщение без точного пути попадает в `details` с `path` равным `null`.
6. Записать объект и зафиксировать транзакцию.
7. Любое исключение отменяет активную транзакцию. Нарушение прав — `403`. Прочее — `500`: краткое представление в ответе, подробное — в журнале регистрации, событие `СчетаМагазина`.

Несколько ошибок преобразования возвращаются вместе. Сообщение конверта при коде `validation` — «Некорректные данные», кроме отказа штатной проверки заполнения.

Контрольный счет использует уже существующие в базе ссылки на организацию, валюту, ответственного, подразделение и партнера. Суммы строк передаются в теле, сервис их не пересчитывает. Обязательные поля счета, которые показывает `GET /type`: дата, партнер, организация, ответственный, подразделение, валюта документа; в строке товаров — номенклатура, цена, сумма, всего.

## Ошибки

Тело любой ошибки:

```json
{
  "error": {
    "code": "validation",
    "message": "Некорректные данные",
    "details": [
      { "path": "header.Наименование", "message": "Недопустимое значение, тип, ограничение или ссылка; ожидается string" }
    ]
  }
}
```

`Content-Type` — `application/json; charset=utf-8`, без BOM.

| Ситуация | HTTP | code |
| --- | --- | --- |
| Пустой параметр, битый JSON, лишняя форма тела, некорректный UUID | 400 | invalid_request |
| Вид метаданных не справочник и не документ | 400 | unsupported_type |
| В теле передано `ЭтоГруппа` | 400 | unsupported |
| Преобразование, владелец, родитель, штатная проверка заполнения | 400 | validation |
| Имя справочника или документа не найдено в метаданных | 404 | unknown_type |
| Объект по UUID не найден | 404 | not_found |
| Нет права чтения или добавления, категория нарушения прав | 403 | forbidden |
| Непредвиденное исключение платформы | 500 | internal_error |

Ошибка клиента — это `4xx` с этим конвертом. `500` зарезервирован для сбоя, который сервис не отнес к отказу клиента.

## Проверка

Среда — опубликованная база БСП 3.2.1. Основная конфигурация не изменяется. Расширение выгружается в `СчетаМагазина.cfe` в корне рабочей копии.

Рядом лежат `objects.http` и `.env`. В запросах нет адреса и учетных данных. В `.env` лежат база, пользователь, пароль и UUID ссылок контрольного примера. Идентификатор созданного партнера для `GET /object` берется из ответа `POST` и записывается в `.env`. Файл `.env` с паролем в коммит не входит.

В `objects.http` по одному запросу на маршрут и два создания:

- `GET /types?q=партнер`
- `GET /type?name=Справочник._ДемоПартнеры`
- `GET /search?type=Справочник._ДемоПартнеры&q=` с непустой строкой
- `GET /object` по идентификатору созданного партнера
- `POST /object` — элемент `_ДемоПартнеры` с наименованием и `ВидПартнера`
- `POST /object` — непроведенный `_ДемоСчетНаОплатуПокупателю`

Контрольный пример: созданные партнер и счет открываются в 1С, счет не проведен.

Отдельно от файла приемки проверяются отказы: создание группы, подчиненный справочник без владельца, неизвестный вид, неизвестный UUID, запись неподдерживаемого поля, чтение объекта с неподдерживаемым значением (`200` и `null`), отсутствие группы в поиске, `hasMore` при более чем 20 строках.

## Вне рамок

Изменение и удаление объектов, проведение документов, регистры, константы, отчеты, обработки, общие реквизиты, запись дополнительных реквизитов БСП, создание групп, постраничная навигация сверх признака `hasMore`.
