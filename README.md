# Регистры сведений: стартовое состояние

Расширение `СчетаМагазина` с сервисом объектов и MCP-сервер `onec-objects` над ним —
в том виде, в каком они работают со справочниками и документами. Для регистров
сведений заготовлен каркас: маршруты сервиса заведены и отвечают `501`, инструменты
сервера объявлены и отвечают заглушкой. Спецификация и план доработки уже написаны.

| Путь | Что это |
| --- | --- |
| `СчетаМагазина.cfe` | расширение для загрузки в базу |
| `src/extensions/СчетаМагазина/` | исходники расширения (XML, формат Hierarchical) |
| `src/mcp/onec-objects/` | MCP-сервер: код, тесты, `README.md` с командами |
| `src/tests/registers.http` | запросы REST Client, по одному на маршрут регистров |
| `src/tests/.env.example` | образец `.env`: адрес, авторизация, идентификаторы демо-данных |
| `docs/superpowers/specs/` | спецификации: сервис объектов, MCP-сервер, регистры |
| `docs/superpowers/plans/` | план доработки регистров |

## Начало работы

1. Загрузите `СчетаМагазина.cfe` в базу из `1Cv8_demo.dt`, опубликуйте базу на
   веб-сервере.
2. Скопируйте `src/tests/.env.example` в `src/tests/.env`, поправьте адрес
   и авторизацию. Любой запрос регистра из `registers.http` должен ответить `501`.
3. Соберите сервер в каталоге `src/mcp/onec-objects`:

   ```bash
   npm ci
   npm run build
   ```

4. Задайте переменные окружения сервера и подключите его к агенту командой
   `node src/mcp/onec-objects/dist/index.js` из корня проекта:

   | Переменная | Значение |
   | --- | --- |
   | `OBJECT_SERVICE_URL` | адрес сервиса объектов, до `/hs/objects` включительно |
   | `OBJECT_SERVICE_USER` | пользователь 1С |
   | `OBJECT_SERVICE_PASSWORD` | пароль; пустой можно не задавать |

   Новый чат агента должен видеть инструменты сервера; инструменты регистров пока
   отвечают «ещё не подключён к сервису объектов».

Адрес и пароль не попадают ни в код, ни в запись подключения, которая лежит в git.
